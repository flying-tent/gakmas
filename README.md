# gakmas
学マスのもろもろの計算ツールです

## MV再生回数(mv.html)

初星学園チャンネルの楽曲MVと音源の再生回数を GitHub Actions(`.github/workflows/update.yml`)が毎時7分ごろに取得し、次のファイルに保存します。

- `data/data.json`:ページ(`mv.html`)が読むファイル。スマホの通信量を小さくするため、表示に要るものだけを載せる(`scripts/build-site.mjs` が作る)
  - 形:`{ updatedAt, prevDate, songs: [{ title, idols, singer?, videos: [{ id, type, date, views, diff?, isNew? }] }] }`
  - `songs` は曲ごと(MV・音源・インストをまとめたもの)。`idols` は歌唱アイドル、`singer` は表示名がアイドル名を「・」でつないだものと違うときだけ付く(「初星学園」など)
  - `videos` は MV → 歌入り音源 → インストの順(歌入り音源は元の版 → ソロ版、それぞれフルサイズ → ゲームサイズ)。`type` は `mv`・`vocal`・`inst`、`date` は公開日(日本時間)、`views` は合計回数、`diff` はその日の回数(その日の最初の記録=0時台の最初の取得からの増加。その日の最初の取得の直後は0。日付が変わる前後の約1時間(前日の最後の取得〜その日の最初の取得)の分はどちらの日にも入らない。新曲は公開からの全回数)、`isNew` は新曲の印、`game` はゲームサイズの音源の印、`solo` はソロ版を歌っているアイドル
  - `prevDate` は `diff` の基準にした記録の日付。基準の記録がないときは `null` で、`diff` は付かない
- `data/state.json`:取得に使う内部の記録(直近3日分の日ごとの記録と、音源の検索結果のキャッシュ)。ページは読まない
- `data/daily/YYYY-MM.json`:その月の日ごとの記録をずっと残す(あとで推移のグラフなどに使う)。1日1行で `{ date, at, views: { 動画ID: 再生回数 }, first: { at, views } }`。その日の値は毎時上書きされ、日付(日本時間)が変わる直前の値が残る。`first` はその日の最初の取得の値(その日の回数 = `views` − `first.views`。この仕組みを入れる前の記録にはない)
- `data/daily/videos.json`:動画IDごとの情報(曲名・種類・公開日・最後に一覧にあった日)。一覧から消えた動画も残す
- ページは最初の表示で `data/data.json` だけを読むので、記録が増えても表示は遅くならない

- APIキー:リポジトリの Secrets に `YT_API_KEY` として登録
- 公開:Settings → Pages → Source を「GitHub Actions」にする(このワークフローがサイト全体を公開します)
- 初回:Actions タブ →「再生回数を記録して公開」→ Run workflow
- 表示確認:`mv.html?demo` でダミー値を表示
- アイドルの色:`mv.html` の `IDOLS`
- 曲名・歌唱者の読み取りと、その手動修正:`scripts/songs.mjs` の `OVERRIDES`(歌唱アイドル)・`TITLE_OVERRIDES`(曲名)。アイドルを増やすときは `scripts/songs.mjs` の `IDOL_NAMES`・`ROMAJI` と、`mv.html` の `IDOLS`・`ROMAJI` の両方に足す
- 手動修正を変えて main に入れると、ワークフローが YouTube API を使わずに `data/data.json` を作り直して公開する(手元では `node scripts/build-site.mjs`)
- 対象:初星学園チャンネルの「Official Music Video」(ショート除く)と、Hatsuboshi Gakuen - Topic の音源(歌入り・インスト。ver. 違い・ゲームサイズ・リミックスは除く。ただし「初 [氷渡香名江 Solo ver.]」のようなアイドルのソロ版は、元の全体曲「初」にまとめて合計する。ゲームサイズとフルサイズは別の動画として数える。動画一覧では元の版の後ろに、アイドル名だけのラベル(「氷渡香名江」、ゲームサイズはさらに「ゲームサイズ」)のラベルを付けて並べ、棒グラフはそのアイドルの色にする。アイドルごとの合計には、そのアイドルのソロ版も足す(アイドルの画面のソロ曲に「初 (ソロ)」として出る)。毎時の取得のログに、数えたソロ版の曲名を出す)。同じ曲のMV・音源・インストは曲名で1曲にまとめて合計する
- 音源が Hatsuboshi Gakuen - Topic 以外(歌唱アイドル名の Topic チャンネルなど)にあるとき:`scripts/fetch.mjs` の `EXTRA_AUDIO_CHANNEL_IDS` にチャンネルIDを足す。Hatsuboshi Gakuen - Topic に同じ曲名があるものは数えない
- 曲名が食い違って別の曲に分かれたとき:`scripts/songs.mjs` の `SONG_ALIASES` で同じ曲としてつなぐ
- 検索:曲名・アイドル名(漢字・ひらがな・ローマ字)で絞り込める。漢字の入った新曲が出たら、`mv.html` の `SONG_READINGS` に読みを足すと、ひらがなでも探せる。アイドルの読みは `IDOLS` の `kana`(姓と名をスペースで区切る)。アイドル表示では、当てはまる曲を歌っているアイドルも出る。歌唱の表示がユニット名だけの曲は、`UNIT_MEMBERS` にメンバーを足すとアイドル名で探せる
- 表示の切り替え:検索欄の右のフィルタボタンで、期間(今日/累計)・表示(曲/アイドル)・「MVだけで集計」を開く。「MVだけで集計」をオンにすると、上の数字・ランキング・動画一覧がすべてMVだけの集計になり、MVのない曲はランキングから外れる。この設定はブラウザ(localStorage の `gakmas.mvOnly`)に覚える
- 表示条件のチップ:検索欄の下(設定を開いているときは設定の下)に、今の表示条件(期間・曲/アイドル・MVだけで集計のときは「MVのみ」)をチップで常に出す。PCでは期間は2つの表の見出しでわかるので出さない。チップをタップするとフィルタボタンと同じく設定を開け閉めする
- PC表示:画面の幅が900px以上のときは、左に「累計」、右に「デイリー」(今日0時からの増加)のランキングを並べる。期間の切り替えは隠し、検索・表示(曲/アイドル)・「MVだけで集計」は両方の表に効く。上の数字は累計で出す。スマホでは今までどおり期間を切り替えて1つの表を出す。スマホの「今日」では、ランキングの各行・ポップアップの今日の回数の下(横)に、総再生回数を数字だけで併記する(上のカードには出さない)。PCでも、曲ごとのデイリーの表と、デイリーの表から開いたポップアップでは同じように併記する。今日の回数には「+」を付けて見分ける。曲ごとのランキングでは、2つめの数字(今日は総再生回数、累計はその日の増加)を右寄せにする(スマホ・PC共通。ポップアップの動画一覧とアイドルの画面の曲の一覧も同じ)。新曲の「NEW」は曲名の行の右端に出す。前日の記録はあるのに前日比が取れない動画・曲(記録を取り始めたばかりのものなど)は、その日の回数・前日比を「-」と出す
- PC表示の上のパネルも、下の表と同じく左に累計・右にデイリーを並べる(それぞれ合計と最多再生MVの2枚を縦に)
- PC表示では、検索欄を左半分、表示の切り替え(曲/アイドル・MVだけで集計)を右半分に1行で並べ(下の表と幅をそろえる)、常に出しておく(フィルタボタンと条件のチップは出さない)
- 境目は900pxの1つだけで、900px未満はタブレットや狭いウィンドウも含めてすべてスマホ表示(上のパネルは縦に積み、サムネイルは小さめ)
- 配色:端末の設定に関係なく、いつもダークモード(暗い紫の背景と枠線)で表示する(色は `mv.html` の `:root`)
- 上の「最多再生MV」のパネルをタップすると、その曲の動画一覧のポップアップを開く(YouTubeは動画一覧の行から開く)

## X への配信(scripts/post-x.mjs)

毎日1回、前日(日本時間)の再生回数ランキングを、画像付きで X に投稿します。

- 投稿の内容:MVだけのランキングと、MV・音源・インストの合計のランキングを、別々の投稿にする(リプライにはしない)。それぞれに TOP10 の画像を1枚付ける
  - 本文:4行。言い回しは日付で決まる候補から選ぶ(日によって変わる。同じ日に作り直しても同じ文)
    1. 何のランキングか(例:「11/27のMVのみのランキングはこちら！」「11/27の全曲ランキングを発表します！」)
    2. 1位の曲。前々日からの変化で言い方を変える(変わらず・○日連続 💪 / 前日○位から浮上 🎉 / 新曲 ✨ / 記録なし 👑)。連続1位は記録をさかのぼって数える
    3. 注目の曲(1位以外の TOP10 から1曲。なければこの行はなし):新しくランクインした曲(新曲、または前々日の11位以下から TOP10 入り)を優先し、なければ3つ以上順位を上げた曲。複数あるときは順位の高い曲 👀 ⤴️
    4. `#学マス #学園アイドルマスター`
    - 再生数は本文に入れない(画像に載っている)。URLは入れない(X API はURL入りの投稿が高いため)
  - 画像の代替テキスト(読み上げ用)に TOP10 を文字で入れる
- 順位:前日の再生数の多い順。順位の変化は前々日の順位と比べる(▲上がった数 / ▼下がった数 / → 同じ / NEW その日に公開された新曲 / - 前々日の記録がない)。前々日に11位以下だった曲も、全曲の順位で比べる
- 画像(`scripts/ranking-image.mjs`):1080×1440 の PNG。HTML で組んで Chrome(ヘッドレス)で撮る
  - 見出しは「初星学園 音楽ランキング」「HATSUBOSHI DAILY CHART」、ロゴは `scripts/x-assets/logo.png`。右上に種類のラベル(「MV」/「全曲」)と集計した日(2026/11/27)
  - 各行:順位(1位は王冠)・歌唱アイドルの色の帯(人数で縦に等分。色は `mv.html` の `IDOLS` から読む。歌唱アイドルがわからない曲はグレー)・曲名とその下に歌唱者・前日の再生数・順位の変化。入りきらない曲名は文字を小さくし、それでも入らなければ「…」で省略する
  - フォントはページと同じ IBM Plex Sans JP(ワークフローが Google Fonts のリポジトリから入れる。取れなければ Noto Sans CJK)
  - 見た目の確認:`node scripts/ranking-image.mjs sample.png` でダミーのランキングの画像を作れる
  - 画像を作れなかったり、アップロードできなかったりしたときは、本文だけで投稿する
- 回数の計算:`data/daily/` の前日の記録から、ページの「今日」と同じ計算(その日の最初の取得からの増加、新曲は公開からの全回数)で出す
- いつ投稿するか:再生回数の記録とは別のワークフロー(`.github/workflows/post-x.yml`「X にランキングを投稿」)で投稿する。このワークフローは自分では起動しないので、起動のしかた(12時ごろに1回など)は別に設定する(手動なら Run workflow)。何時に何回起動しても、前日分をまだ投稿していないときだけ投稿する(1日1回)。投稿したことは `data/x-post.json` に残す。失敗したら、もう一度起動すれば残りだけ投稿する
- 強制投稿:「X にランキングを投稿」の Run workflow で「強制投稿」にチェックを入れると、投稿済みかを確かめずに前日分を2件とも投稿する(同じ日の分がもう一度出る)。「お試し実行」と両方チェックしたときはお試し実行になる。最近の投稿と本文がまったく同じときは X に断られて失敗する。手元では `node scripts/post-x.mjs --force`
- 投稿しないとき:前日の最後の記録が22時より前(夜の取得が抜けている)、または回数の基準になる記録がないときはログに理由を出して投稿しない
- キー:X の Developer Console でアプリを作り、OAuth 1.0a の読み書きの権限で、投稿するアカウントの API Key / API Key Secret / Access Token / Access Token Secret を作って、Secrets に `X_API_KEY`・`X_API_SECRET`・`X_ACCESS_TOKEN`・`X_ACCESS_TOKEN_SECRET` として登録する。登録していないあいだは投稿しない
- 費用:X API は従量課金(クレジットを先に買う)。1日2件で、月に60件ほど(画像のアップロードの分は Console で確認)
- 試し方:`node scripts/post-x.mjs --dry-run`(前日)または `node scripts/post-x.mjs --dry-run 2026-11-26` で、投稿文と代替テキストをログに出し、画像を `x-images/` に作る。「X にランキングを投稿」の「お試し実行」では、画像を Artifacts(`x-images`)に残す
- 変えたいとき:件数・ハッシュタグ・呼び方は `scripts/post-x.mjs` の先頭の `TOP_N`・`HASHTAGS`・`KINDS`。本文の言い回しは `topLine`・`highlightLine`・`postText` の候補

## アクセス解析と週次レポート(analytics.js・scripts/weekly-report.mjs)

Google アナリティクス 4(GA4)でアクセスを計測し、毎週の数字と AI(Gemini)の改善案を Issue にします。

- 計測:各ページの `<head>` で `analytics.js` を読む。`analytics.js` の `GA_ID` に測定ID(`G-` から始まる)を入れると計測を始める(空なら何も送らない)。手元(localhost・file:)と `?demo` では送らない。Google シグナルと広告のカスタマイズは切ってある
- mv.html の操作イベント(`mv.html` の `logEvent`):`open_song`(曲のポップアップ。`song_title`・`from`)・`open_idol`(アイドルのポップアップ。`idol`。「戻る」は数えない)・`open_youtube`(`song_title`・`video_type`)・`change_setting`(`setting` = view / unit / mvOnly、`value`)・`search`(`search_term`)。どのイベントにも、そのときの `period`(today / total)・`unit`・`mv_only`・`layout`(pc / mobile)を付ける
- 計測していることは `privacy.html`(アクセス解析について)に書き、各ページの下からリンクしている。送る内容を変えたらそちらも直す
- 週次レポート:`.github/workflows/weekly-report.yml`「週次アクセスレポート」が毎週月曜の朝(日本時間9時ごろ)に、前の週(月〜日)の数字をその前の週と比べて集め、Gemini に改善案を書かせて Issue にする。AI に渡すのは集計した数字と、この README の「MV再生回数」の画面の説明だけ。AI が失敗しても数字だけで Issue を作る。手動なら Run workflow(「お試し実行」で Issue を作らずログに出す)
- 試し方:`node scripts/weekly-report.mjs --dry-run --sample`(ダミーの数字。`GEMINI_API_KEY` があれば AI の案も出る)

### 初めの設定

1. GA4:[Google アナリティクス](https://analytics.google.com/)でプロパティを作り(タイムゾーンは日本)、ウェブのデータストリームにサイトの URL を登録する。測定ID を `analytics.js` の `GA_ID` に入れる
2. カスタムディメンション:GA の「管理 → カスタム定義」で、イベントスコープのディメンションを次のパラメータ名で登録する:`setting`・`value`・`song_title`・`idol`・`video_type`・`period`・`layout`・`search_term`(未登録の表はレポートで「取れませんでした」と出るだけで、ほかは動く。登録した日より前の分は取れない)
3. データ保持:「管理 → データの収集と修正 → データ保持」を14か月にしておく(週次レポートは直近2週しか使わないが、あとで振り返るとき用)
4. サービスアカウント:[Google Cloud](https://console.cloud.google.com/) でプロジェクトを作り、「Google Analytics Data API」を有効にする。サービスアカウントを作って鍵(JSON)を発行し、そのメールアドレスを GA の「管理 → プロパティのアクセス管理」に「閲覧者」で追加する
5. Gemini:[Google AI Studio](https://aistudio.google.com/) で API キーを作る(無料枠で足りる。無料枠では送った内容が Google の改善に使われるので、渡すのは集計した数字だけにしている)
6. リポジトリの Secrets に `GA_PROPERTY_ID`(プロパティID の数字)・`GA_SA_KEY`(鍵の JSON をそのまま)・`GEMINI_API_KEY` を登録する。モデルを変えたいときは Variables に `GEMINI_MODEL`(省略時は `gemini-2.5-flash`)
